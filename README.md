# 陶瓷窑车层架载荷追踪台

按 **自下而上** 的方式录入窑车台面、各层矩形棚板（位置/尺寸/自重）、坯件重量，
以及承托该层棚板的立柱坐标与容量。系统根据立柱底端坐标自动判定它落在哪一块
下层棚板（底层落在窑车台面）上，**自上而下逐层分摊、逐层累加**立柱载荷，并在
俯视图 / 侧视图中标出三类风险立柱：

| 标记 | 判定规则 | 含义 |
| --- | --- | --- |
| 🟪 悬空 `hang` | 立柱底端坐标不在承托面（下层棚板或窑车台面）矩形内 | 该柱不受力，本层载荷改由其余有效柱承担 |
| 🟧 落点重叠 `overlap` | 同层两根及以上立柱底端平面距离 ≤ 10 mm | 踩在同一落点，对下层棚板的点载荷合并累加 |
| 🟥 超载 `overload` | 立柱实际分配载荷 > 该柱容量 | 立柱过载，需要加柱 / 减载 / 换大容量柱 |

点击任意立柱可查看其 **载荷来源明细**（本层棚板自重、坯件、以及从更上层逐级
传递下来的每一根立柱的贡献链，例如 `第三层（顶层）·P5 → 第二层·P1`）；
点击棚板可查看该板的承受/下传载荷汇总。**修改任一层输入后整架自动重算**
（250 ms 防抖）并保存到服务端，刷新页面不丢数据。

另有 **立柱失效推演（What-if）**：在结果区勾选一根或多根非悬空立柱为“失效柱”，
系统以当前编辑数据为基准，把失效柱视为不承载后按原规则整架重新分摊，
并排对比基准/推演的台面载荷、丢失载荷与每根立柱载荷差值，并单独列出推演
新增的超载/无支撑项；失效标记只存在于会话内、**不保存**，清空选择立即恢复基准。

还有 **加柱建议**：选择目标层、设置候选网格间距与新柱容量后，后端仅在该层
**承托面内**、且与现有**有效柱**底端距离严格大于重叠阈值（10 mm）的网格点上，
逐点试算新增一根立柱，按「丢失载荷 → 超载数 → 最高利用率（容量 0 不计）→
坐标」升序返回前 5 个方案。面板并排对比基准与各方案的**逐层载荷**与
**新增/消除告警**；点击方案即在俯视图预览新柱位置，**确认后才写入架体并
触发原有自动保存**，取消预览不改动任何数据；没有可行点时会明确给出限制原因。

另有 **减载配额试算**：以当前架体为基准，**只下调各层坯件重量**
（棚板 / 立柱 / 坐标 / 容量均不变），在每层减量不超过现有坯件重量的条件下，
求让全部有限容量立柱不再超载的**最小总减载量**。多层坯件载荷会沿现有
「刚性棚板、有效柱均摊、悬空不承载、无有效柱则丢失」的整架分摊规则共同压到
下层立柱，因此每个有限容量层给出一个「后缀减量和」下界，后端按闭式最优解
分配各层减量（优先减最靠近超载层的本层坯件，不足再由近及远向上层回补），
求得方案后再用同一套规则**重新整架校验**。面板列出每层**原重量、建议重量、
本层减量**以及减载前后的**超载柱数**与**丢失载荷**；若**全部坯件清空仍有
超载**（棚板自重等结构载荷已超容量），明确提示无解并列出**剩余超载柱**。
试算**不写入状态**，点「✓ 按建议重量减载并保存」后才更新坯件重量并沿用
原有自动保存；架体一经编辑，旧方案立即作废。

另有 **层架抗倾覆试算**：沿用当前编辑的架体，以**各层累计高度**作为该层棚板
与坯件的重心高度、**棚板中心**作为两者水平重心，把各层「棚板自重 + 坯件重量」
当作一个质点，**按重量求整架重心**；取**底层非悬空立柱落点的凸包**作为支撑
多边形。输入**水平加速度 x / y 分量（单位 g，可正可负）**，重心水平投影按
「加速度 × 重心高度」等效平移（惯性力 `m·a`，`a` 以 g 计），再计算投影点到
**支撑多边形边界的带符号最短距离**：

| 结果 | 条件 | 含义 |
| --- | --- | --- |
| 🟢 稳定 `stable` | 距离 > 0 | 投影在支撑多边形内，尚有正裕量（mm） |
| 🟡 临界 `critical` | 距离 = 0 | 投影恰落在支撑边界上 |
| 🔴 倾覆 `overturn` | 距离 < 0 | 投影越出支撑多边形 |

俯视图同步叠加**蓝色虚线支撑边界、底层支撑点、整架重心环、平移箭头与按判定
着色的投影点**，面板另列出整架总重、重心 (x, y, z)、平移量、带符号距离与逐层
质点明细。**底层非悬空落点不足以形成非零面积凸包**（少于 3 个不共线落点）、
**任一层无有效承托**（立柱全部悬空或未录入）、整架重量为 0 或没有层时，
**明确返回「无法评估」及原因**，不出判定。试算为**只读 API、不写盘**，
任何架体编辑（含加柱/减载确认写入）都会使旧试算立即失效，需重新试算。

另有 **逐层装货顺序规划**：在抗倾覆试算旁，以**当前架体**为准、**保留全部
棚板自重**，先把所有层**坯件重量置零**，再把**坯件重量大于零的层**（至多
**12** 个候选层）按**整层坯件一次加入**的方式模拟装货。输入**水平加速度
x / y 分量（单位 g）**，对每个**已装子集**（含坯件全零的初始状态）用与抗
倾覆试算完全相同的模型求**带符号裕量**，并用**位掩码动态规划**找出使
「**全过程最小裕量最大**」的加入顺序；最优值相同时按**层序号字典序**
（自下而上）选取，结果确定。面板逐步展示**本步新增层、累计坯件重量、
总重/重心/投影、带符号裕量与稳定判定**（🟢稳定 / 🟡临界 / 🔴倾覆），并给出
最优顺序链与全过程最小裕量；**若最优顺序仍有非正裕量**（含临界 0），明确
标明「**无法全程稳定**」。**无有效承托、底层支撑凸包退化、初始棚板总重为
零、没有层或没有可装层**时返回「无法规划」及原因，**候选层超过 12 层**时
提示缩减规划范围（将部分层坯件置零）。规划为**只读 API、不写盘**，架体
一经编辑旧结果立即作废，需重新规划。

另有 **连续窑门通行试算**：在结果区「🚪 连续窑门通行试算」面板按**行进顺序**
录入每道窑门的**开口横向中心、宽度、高度**以及进入该门前**一段行程的最大横移量**
（单位均为 mm；可用 ▲▼ 调整门序、✕ 删除），**首门从横移 0 的位置出发**。
后端由**窑车台面与各层棚板的 X 向跨度**求架体**横向外廓**（立柱不计），
**累加各层层高**求架体最高点（与重量无关）。逐道门计算架体可通过的**横移闭
区间**：

- **门高 < 架体最高点 → 高度不足，直接判为该门阻断**（不再给横移区间，
  并列出顶部还差多少 mm）；
- 否则本门可通过的横移区间 = 台面/各棚板平移后都落进门开口内的区间之交，
  区间自身为空即**单门宽度不足**；
- 再**按门序**把上一道门后的可达区间按本段最大横移量**扩张**（`[lo-m, hi+m]`）
  后与本门区间**求交**；**首次交集为空即在该门阻断**——即使每道门单独都能给
  出横移区间（「各门单独能过、序列却不可达」）也**不得报可通行**，面板会指出
  阻断门、冲突的两个区间与缺口（mm）。

**全程可达时**，后端回溯一条满足各段横移限制的**位置序列**（末门取可达区间中
最靠近 0 的横移，自后向前逐段 clamp），并逐门给出**选定横移、本段实际移动量与
左 / 右 / 顶部净空**（端点刚好接触、净空 0 视为可通过）。试算**只读取当前编辑
架体、不写盘**，窑门参数仅存于浏览器；**架体或门参数一改变，旧结果立即标记失效**
并防抖自动重算，也可点「开始通行试算」手动触发。架体没有任何层时返回
「无法评估」及原因；窑门参数非法（非数值、宽度/高度非正、横移量为负）返回 400。

另有 **轮组承载试算**：窑车台面承接底层立柱载荷后，用「🛞 轮组承载试算」面板
核对四个车轮是否超额受力。填写台面内的**左 / 右轮位 X 坐标**（`xLeft < xRight`）、
**前 / 后轮位 Y 坐标**（`yFront < yRear`，单位 mm）与**四轮各自的额定载荷**
（左前 FL / 右前 FR / 左后 RL / 右后 RR，kg）。后端以**底层非悬空立柱的落点与
实载为点载荷**（悬空柱不承载、不参与；重叠落点在分配时合并为一个点），按
**矩形四轮的双向杠杆（双线性）比例**分配反力：单个点载荷 P(x,y) 的
`左列份额=(xRight−x)/轮距`、`右列份额=(x−xLeft)/轮距`，
`前行份额=(yRear−y)/轴距`、`后行份额=(y−yFront)/轴距`，四轮份额为两组的
两两乘积、对平面任意位置恒和为 1。因此**落点越出轮组矩形时允许外推**——远端
车轮的份额变为负数，**绝不把负反力截为零**（否则竖向力与绕 X/Y 轴力矩都不再
平衡）；负反力表示该轮实际需要向下拉住台面，存在台面上翘/脱轮风险，会单独标红。

页面逐轮显示**轮位、额定载荷、反力、利用率**与**超载 / 负反力**标记，列出每个
底层点载荷（含落点重叠、越出轮组矩形的外推标记），并给出**平衡核对**：四轮
反力之和与点载荷合计、**绕 X 轴**（过前轮 `y=yFront`）与**绕 Y 轴**（过左轮
`x=xLeft`）的力矩，反力侧与点载荷侧的差值（残差）及一致性判定。**轮距不正**
（坐标相等或顺序颠倒）、**轮位越出台面矩形**、**额定载荷非正**时报**参数错误**
（HTTP 400）；**底层没有正载荷**（如全部悬空、零重量）时明确说明无法试算。
试算**只读、不写盘、不修改已保存架体**，轮位参数仅存于浏览器；**编辑架体后旧
结果立即失效**，轮组矩形与四轮反力会同步叠加在俯视图（橙色虚线矩形 + 车轮方块，
绿色正常、红色超载/负反力，越出矩形的点载荷用橙色 ◇ 标出）。

## 一条命令启动

需要本机已安装 Docker（含 Compose 插件 v2）。

```bash
docker compose up --build -d
```

这是**唯一需要的启动命令**：容器启动时自动完成依赖安装（镜像构建阶段）与
初始化（缺失的 `data/state.json` 由内置示例数据生成），随后启动 Web 服务。

启动后浏览器访问：

> **http://localhost:8000** （页面地址；默认宿主机端口 **8000**，由 `HOST_PORT` 决定）

REST API 与页面同端口、以 `/api/...` 为前缀，例如：

> - 页面：`GET  http://localhost:8000/`
> - 状态：`GET/PUT http://localhost:8000/api/state`（读取带版本号，保存用 `If-Match` 乐观锁，冲突返回 409）
> - 抗倾覆试算：`POST http://localhost:8000/api/overturn`（只读）
> - 逐层装货顺序规划：`POST http://localhost:8000/api/loading-sequence`（只读）
> - 连续窑门通行试算：`POST http://localhost:8000/api/door-passage`（只读）
> - 轮组承载试算：`POST http://localhost:8000/api/wheel-load`（只读）
> - 完整接口清单见下方「HTTP 接口」一节

首次启动会自动把内置 **示例数据**（`data/sample_state.json`，一个 3 层窑车，
内含悬空、落点重叠、超载各一例）复制为可编辑的 `data/state.json`；之后所有
编辑都保存在这个文件里，容器重启数据不丢（通过 `./data` 目录挂载）。

停止 / 查看日志：

```bash
docker compose down        # 停止
docker compose logs -f     # 查看日志
```

## 必要配置

默认无需任何配置。仅当 8000 端口被占用时，在启动前指定宿主机端口：

```bash
HOST_PORT=9000 docker compose up --build -d   # 访问 http://localhost:9000
```

也可以创建 `.env` 文件持久化该配置：

```env
HOST_PORT=9000
```

| 配置项 | 位置 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `HOST_PORT` | compose 环境变量 | `8000` | 宿主机映射端口 |
| `PORT` | 容器环境变量 | `8000` | 容器内 gunicorn 监听端口（一般无需改） |
| `KILN_DATA_DIR` | 容器环境变量 | `/app/data` | 状态 JSON 存放目录，已挂载到宿主机 `./data` |

恢复内置示例：页面右上角 **「↺ 恢复示例」** 按钮（会覆盖当前编辑），
或删除宿主机 `data/state.json` 后重启容器。

## 操作说明

1. **录入架体**：左侧面板自下而上编辑台面尺寸、各层棚板（位置/尺寸/自重）、
   坯件重量与立柱（底端坐标/容量）；任意修改约 250 ms 后整架自动重算并保存，
   顶栏显示保存状态，刷新页面不丢数据。同一窑车在**多个页面/标签**同时编辑时，
   保存携带读取时的架体版本；若期间已被其他页面保存，本页**保留未保存草稿**并在
   顶部红字提示版本冲突（不会显示“已保存”），可选择放弃编辑载入最新架体，或
   保留草稿强制覆盖（详见下方「多页面并发编辑」一节）。
2. **查看结果**：右侧俯视图 / 侧视图实时刷新；点击立柱或棚板查看载荷来源链；
   「告警与判定」列出悬空、落点重叠、超载、无支撑等问题，点击条目可定位到
   对应立柱/棚板。
3. **立柱失效推演**：在结果区「🔮 立柱失效推演」面板勾选一根或多根
   **非悬空**立柱（悬空柱本就不承载，不可勾选）：
   - 系统以当前编辑数据为基准，将失效柱视为不承载后整架重新分摊；
   - 面板并排显示基准 → 推演的**台面载荷**、**丢失载荷**及**每根立柱载荷差值**，
     并单独列出推演后**新增的超载 / 无支撑项**（点击条目可定位）；
   - 视图中失效柱为粉色 ⊘ 标记（原悬空柱仍为紫色 ✕），点击任意立柱仍可查看
     推演后的载荷来源链；失效柱明细会标注其基准载荷去向；
   - 失效标记仅本次会话有效，**不会改写或自动保存**架体数据；
     点击「✕ 清空选择 · 恢复基准」立即回到基准结果；
   - 推演进行中继续编辑架体，会以新数据为基准自动重跑推演。
4. **加柱建议**：在结果区「🧱 加柱建议」面板选择**目标层**，填写候选网格间距
   （mm）与新柱容量（kg，0=不限容量），点击「开始试算」：
   - 后端在该层承托面（底层为窑车台面，其余为下层棚板）内按网格逐点试算，
     仅保留落在承托面内、且与现有**有效柱**距离严格大于 10 mm（`TOL_MM`）
     的候选点；每个点都按原规则整架重算一次；
   - 结果按 **丢失载荷 → 超载柱数 → 最高利用率（容量为 0 的柱不计利用率）
     → 坐标 (x, y)** 全部升序，只返回前 **5** 个方案；
   - 每个方案卡片展开后列出基准 → 方案的**逐层**本层总载荷、丢失载荷、
     下传载荷、超载柱数，以及**新增告警 / 消除告警**（点击条目可定位）；
   - 点击方案卡片，俯视图用金色 ⊕ 标记**预览**新柱落点与试算后载荷；
     此时架体数据**不会改变**，点「✕ 取消预览（不改数据）」随时撤销预览；
   - 点「✓ 确认加柱并保存」才会把该柱追加到目标层，随后走原有编辑通道
     自动重算并保存；继续编辑架体会使旧的试算结果自动作废，需要重新试算；
   - 若承托面为空、候选点全部落在重叠阈值内、或网格过密（> 4096 个候选点），
     面板会明确说明限制原因与调整建议（加大间距 / 调整现有柱 / 更换目标层）。
5. **减载配额试算**：在结果区「⚖️ 减载配额试算」面板点击「开始减载试算」：
   - 后端以当前架体为基准，只调整各层**坯件重量**（0 ≤ 减量 ≤ 现有重量），
     几何与立柱容量完全不动；多层载荷按现有整架分摊规则共同下传，按嵌套后缀
     约束求消除全部有限容量立柱超载的**最小总减载量**（闭式最优，非穷举）；
   - 面板汇总减载前后的**超载柱数**、**最小总减载量**、**丢失载荷**与
     **传到台面载荷**，并逐层列出**原坯件重量 → 建议重量、本层减量、
     超载柱数（前→后）、丢失载荷（前→后）**，结果均经同一套规则重新整架校验；
   - 试算**不写入状态**：点「✓ 按建议重量减载并保存」确认后才把建议坯件重量
     写入架体，随后走原有编辑通道自动重算并保存；「✕ 取消试算」随时放弃；
   - 继续编辑架体会使旧方案自动作废，需要重新试算；
   - 若**全部坯件清空仍有超载**，面板标注「无解」，列出清空后仍超载的
     立柱（层、编号、载荷、容量）与原因，此时只能加柱 / 换大容量柱 / 减轻棚板自重。
6. **层架抗倾覆试算**：在结果区「📐 层架抗倾覆试算」面板填写水平加速度
   **ax / ay（单位 g，可正可负，0=静止）**，点击「开始抗倾覆试算」：
   - 后端以各层**累计高度**为棚板/坯件重心高度、**棚板中心**为水平重心，
     按重量加权求整架重心，取**底层非悬空立柱落点凸包**为支撑多边形；
   - 投影按 `(ax·Gz, ay·Gz)` 平移后，计算到支撑边界的**带符号最短距离**：
     正=🟢稳定、0=🟡临界、负=🔴倾覆；面板给出整架总重、重心、平移量、
     距离裕量与逐层质点明细；
   - 俯视图叠加蓝色虚线**支撑边界**、底层落点、蓝色**整架重心**环、平移箭头
     与判定色的**投影点**（顶视图例可对照颜色）；
   - 落点少于 3 个不共线点（凸包面积为 0）、任一层无有效承托、整架重量为 0
     或没有层时，面板明确显示**无法评估**及原因，不输出稳定/倾覆判定；
   - 试算**只读、不写盘**；修改 ax/ay 会防抖自动重算，而一旦**编辑架体**
     （含加柱/减载确认写入或恢复示例），旧试算立即失效并从俯视图清除，
     需重新点击试算；「✕ 清空试算」可随时收起叠加层。
7. **逐层装货顺序规划**：在「📐 层架抗倾覆试算」旁的「🚚 逐层装货顺序规划」
   面板填写水平加速度 **ax / ay（单位 g，可正可负，0=静止）**，点击
   「开始装货顺序规划」：
   - 后端以**当前架体**为准、**保留全部棚板自重**，先把全部**坯件重量置零**，
     再取**坯件重量大于零的层**作为候选层（**至多 12 个**），按**整层坯件
     一次加入**枚举装货过程；
   - 对**每个已装子集**（含初始无坯状态）按与抗倾覆试算相同的重心/凸包/
     等效偏心模型计算**带符号裕量**，用**位掩码动态规划**（≤ 4096 个子集）
     求「全过程最小裕量」最大的加入顺序，**同分按层序号字典序**（自下而上）；
   - 面板逐步列出**本步新增层、累计坯件重量、整架总重、重心/投影、带符号
     裕量与 🟢稳定/🟡临界/🔴倾覆判定**，并给出**最优装货顺序链**、初始/终态
     裕量与全过程最小裕量（及所在步）；
   - 若**最优顺序的全过程最小裕量仍 ≤ 0**，顶部明确标注「**无法全程稳定**」
     （临界 0 同样视为不稳定）；
   - **任一层无有效承托、底层支撑凸包退化（不足 3 个不共线落点）、初始棚板
     总重为 0、空架或没有坯件重量大于零的层**时，面板明确显示**无法规划**及
     原因，不出顺序；候选层 **超过 12 层**时提示**缩减规划范围**（把暂不规划
     的层坯件重量置零）；
   - 规划**只读、不写盘**；修改 ax/ay 会防抖自动重算，而一旦**编辑架体**
     （含加柱/减载确认写入或恢复示例），旧规划立即作废，需重新规划；
     「✕ 清空规划」可随时收起结果。
8. **连续窑门通行试算**：在「🚚 逐层装货顺序规划」下方的「🚪 连续窑门通行试算」
   面板按行进顺序录入窑门（每行依次为**开口横向中心 c / 宽度 w / 高度 h /
   本段最大横移量**，单位 mm；▲▼ 调整门序、✕ 删除，「＋ 增加一道门」追加）：
   - 后端以**窑车台面与各层棚板的 X 向跨度**为横向外廓、**累加层高**为最高点；
     每道门先判**高度**（不足直接阻断），再求本门可通过的**横移闭区间**；
   - 按门序把上一道门后的可达区间**按本段横移量扩张**后与本门区间**求交**，
     **首次交集为空即在该门阻断**：面板标出阻断门序号、本门区间、扩张后区间、
     缺口与阻断类型（高度不足 / 单门宽度不足 / 横移序列不可达），阻断门之后
     的门标记为「未评估」；**各门单独能过但序列不可达同样判阻断**；
   - 全程可达时顶部给出**位置序列**（每门选定横移与本段移动量），表格逐门列
     开口沿、本门区间 / 扩张区间 / 交集、**左 / 右 / 顶部净空**与判定；
   - 试算**只读、不写盘**；门参数改动后防抖自动重算，**架体或门参数一改变旧
     结果立即标记失效**（状态徽章变「结果已失效」），点「✕ 清空试算」可收起。
9. **轮组承载试算**：在「🛞 轮组承载试算」面板填写**左/右轮位 X 坐标 xLeft/xRight**
   （须 `xLeft < xRight`）、**前/后轮位 Y 坐标 yFront/yRear**（须 `yFront < yRear`，
   mm，四个轮位都必须在台面矩形内）与 **FL/FR/RL/RR 四轮额定载荷**（kg，必须为正），
   点击「开始轮组试算」：
   - 后端以**底层非悬空立柱的落点与实载为点载荷**，按矩形四轮的**双向杠杆比例**
     分配反力；**落点越出轮组矩形时外推，负反力不截零**；
   - 表格逐轮列出**轮位、额定载荷、反力、利用率**与**超载/负反力**标记，并列出
     每个点载荷的落点、实载、重叠与外推状态；下方**平衡核对**表给出反力之和与
     绕 X/Y 轴力矩的反力侧、点载荷侧、残差及一致性判定；
   - 俯视图叠加**橙色虚线轮组矩形**与四个**车轮方块**（绿=正常、红=超载/负反力，
     负反力方块带向下箭头），越出轮组矩形的点载荷用橙色 ◇ 标出；
   - **轮距不正、轮位越出台面、额定载荷非正**时顶部显示参数错误（HTTP 400）；
     **底层没有正载荷**时明确显示无法试算及原因，不出逐轮结果；
   - 试算**只读、不写盘**；轮参数改动后防抖自动重算，**编辑架体（含加柱/减载
     确认写入或恢复示例）后旧结果立即失效**，点「✕ 清空试算」可收起叠加层。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/state` | 读取当前架体输入（首次自动生成示例）；响应头 `ETag` / `X-Frame-Version` 给出当前架体版本号（正整数） |
| `PUT` | `/api/state` | 保存架体 JSON，并返回整架重算结果（前端每次编辑调用）。支持**乐观锁版本**：请求头 `If-Match: "版本号"`（也支持 `X-Frame-Version` 头或 body 顶层 `version` 字段）携带读取时版本，服务端在一次加锁写入中核对——匹配才提交完整架体并把版本 +1；不匹配返回 **HTTP 409**，body 含 `{"conflict": true, "version": 最新版本, "state": 最新已保存架体, "result": 其重算结果}`，不写入任何内容。不带版本的调用按原语义执行（总是写入），但版本同样 +1；`If-Match: *` 表示不校验版本强制写入 |
| `POST` | `/api/recalc` | 仅重算：body 传架体 JSON（不传则用已保存状态） |
| `GET` | `/api/result` | 已保存状态的重算结果 |
| `POST` | `/api/simulate` | 立柱失效推演：body `{"state": 架体JSON(可省), "failed": [{"layer": 0, "post": "P1"}]}`，返回 `{baseline, simulation, failed, diff}`（基准/推演/生效失效柱/差值）；**只计算，不写盘**，失效标记不持久化 |
| `POST` | `/api/suggest` | 加柱建议：body `{"state": 架体JSON(可省), "layer": 2, "spacing": 100, "capacity": 300}`；在目标层承托面内按候选网格逐点试算新增一根立柱，按丢失载荷/超载数/最高利用率/坐标升序返回前 5 个方案（含逐层载荷与新增/消除告警对比）；**只计算，不写盘**，参数非法返回 400，无可行点返回 200 + `reason`；确认加柱由前端走 `PUT /api/state` 完成 |
| `POST` | `/api/load-shed` | 减载配额试算：body `{"state": 架体JSON(可省)}`；只下调各层坯件重量，按现有整架分摊规则构建嵌套后缀减量约束，求消除全部有限容量立柱超载的最小总减载量并重新整架校验；返回 `feasible`、`totalReduction`、逐层 `wareOriginal/wareSuggested/reduction` 与减载前后超载数、丢失载荷，以及 `baseline/trial` 完整结果；无解（全部清空仍超载）时 `feasible=false` 并给出 `remainingOverloads` 与 `reason`；**只计算，不写盘**，确认减载由前端走 `PUT /api/state` 完成 |
| `POST` | `/api/overturn` | 层架抗倾覆试算（只读）：body `{"state": 架体JSON(可省), "ax": 0.1, "ay": 0}`（水平加速度分量，单位 g，默认 0）；按各层累计高度/棚板中心求整架重心 `cg(x,y,z)` 与 `totalWeight`，以底层非悬空立柱落点凸包为 `polygon`，投影按 `(ax·Gz, ay·Gz)` 平移得 `projection`，返回到支撑边界的带符号最短距离 `margin`（mm，内正/边界 0/外负）与 `verdict`（`stable`/`critical`/`overturn`），附 `shift`、`supportPoints` 与逐层质点明细；落点凸包面积为 0、任一层无有效承托、总重为 0 或空架时 `evaluable=false` 并给出 `reason`、`unsupportedLayers`；加速度非数值返回 400；**不写盘、不改已保存状态** |
| `POST` | `/api/loading-sequence` | 逐层装货顺序规划（只读）：body `{"state": 架体JSON(可省), "ax": 0.1, "ay": 0}`（水平加速度分量，单位 g，默认 0）；保留全部棚板自重、坯件先全部置零，再取坯件重量大于零的层（`candidates`，至多 12）按整层一次加入，对各已装子集（含初始状态）求与 `/api/overturn` 相同的带符号裕量，用位掩码动态规划求全过程最小裕量最大的加入顺序 `order`（同分按层序号字典序），返回逐步 `steps`（新增层/累计坯件重量/总重/重心/投影/裕量/`verdict`/`stable`）、`minMargin`、`minMarginStep` 与 `allStable`（任一步非正即 false）；无有效承托、底层支撑凸包退化、初始棚板总重为 0、空架或无可装层、候选层超过 12 时 `planable=false` 并给出 `reason`；加速度非数值返回 400；**不写盘、不改已保存状态** |
| `POST` | `/api/door-passage` | 连续窑门通行试算（只读）：body `{"state": 架体JSON(可省), "doors": [{center,width,height,maxShift}, ...]}`，窑门按行进顺序排列，字段为开口横向中心、宽度、高度与进入该门前本段最大横移量（单位 mm），首门从横移 0 出发；由台面与各棚板 X 向跨度给 `profile`（`totalHeight`=累加层高、`envelope`、逐件 `slabs`），逐门返回本门可通过横移闭区间 `interval`、上一可达区间扩张后的 `reachExpanded`、两者交集 `reachable` 与阻断信息；门高 < 最高点时 `blockReason="height"` 直接阻断（无 `interval`），本门区间自身为空为 `"width"`，扩张后与本门区间无交为 `"reach"`（附 `conflict`：两个区间与缺口）；首次空交集即 `passable=false`、`blockedAt` 指向阻断门、其后各门 `evaluated=false`；全程可达时 `positions` 给出回溯的每门选定横移 `shift`、本段移动 `move`（≤ `maxShift`）与左/右/顶部净空 `clearance`；空门列表按可达处理（附 `note`）；没有任何层时 `evaluable=false` 并给出 `reason`；`doors` 非数组、字段非有限数值、宽度/高度非正或横移量为负返回 400；**不写盘、不改已保存状态** |
| `POST` | `/api/wheel-load` | 轮组承载试算（只读）：body `{"state": 架体JSON(可省), "xLeft","xRight","yFront","yRear"(台面内轮位坐标 mm), "ratedFL","ratedFR","ratedRL","ratedRR"(四轮额定载荷 kg)}；也支持 `{"wheels": {"FL": {"x","y","rating"}, ...}}` 分组形式。以底层非悬空立柱的落点与实载为点载荷（重叠落点合并），按矩形四轮双向杠杆（双线性）比例分配反力，落点越出轮组矩形时允许外推、**负反力不截零**；返回 `trackX/wheelbaseY`、逐轮 `wheels`（`reaction/rating/utilization/overloaded/negative`）、点载荷明细 `pointLoads`（含 `outsideWheelRect` 外推标记）、风险 `risks`（`wheel-overload` / `negative-reaction` / `extrapolation`）与平衡核对 `checks`（`force` 反力之和、`momentX` 绕过前轮 X 轴力矩、`momentY` 绕过左轮 Y 轴力矩，各含反力侧/点载荷侧/`residual`/`ok`）；轮距不正（`xLeft≥xRight`/`yFront≥yRear`）、任一轮位越出台面矩形、额定载荷非正返回 400；没有底层或底层非悬空柱正载荷合计为 0 时 200 + `evaluable=false` 与 `reason`；**不写盘、不改已保存状态** |
| `POST` | `/api/reset` | 恢复内置示例数据；无论内容是否变化都把版本 +1（响应同样带 `version` / `ETag`），使重置前发出、携带旧版本的保存事后到达时只会收到 409，不能覆盖重置结果 |

## 多页面并发编辑：架体版本与冲突处理（乐观锁）

同一辆窑车可能在两个页面 / 标签（或两个 API 调用方）同时编辑。架体带有一个
**单调递增的整数版本号**（保存在 `data/state.meta.json`，架体 JSON 自身的
`car` / `layers` 结构不变）：

- `GET /api/state` 读取架体时，响应头 `ETag: "3"` 与 `X-Frame-Version: 3`
  给出当前版本；
- 保存时用 `If-Match: "3"` 把**读取时的版本**带回服务端，服务端在**一次加锁
  写入**中完成「核对版本 → 保存完整架体 → 版本 +1」：版本匹配才提交，不匹配
  返回 **409 Conflict** 且不写入，响应体给出最新已保存架体与版本；
- `POST /api/reset` 恢复示例时也会把版本 +1（即使内容相同），因此重置前发出、
  重置后才到达的旧保存会被 409 拒绝，不能事后覆盖示例；
- **不带版本的调用完全兼容**：直接 `PUT` 架体 JSON 仍按原语义写入，且版本照常
  +1。`If-Match: *` 表示显式强制覆盖（不校验版本）。

页面端行为：编辑请求串行发送、每个请求携带当前已知版本；若收到 409，左侧
录入面板**保留未保存草稿**，顶栏显示红色「⚠ 版本冲突：架体已在别处保存，
草稿未保存」（绝不显示“已保存”，也不用本地试算冒充已保存），结果区展示服务端
最新已保存架体，并提供两个按钮：**放弃我的编辑，载入最新架体** 或
**保留我的编辑并强制覆盖**。同一页面连续编辑中较早发出的请求响应不会覆盖
较新草稿；恢复示例后，在途旧请求的响应一律作废。

读取（注意响应头里的版本号）：

```bash
curl -s -D - http://localhost:8000/api/state -o /tmp/frame.json
# HTTP/1.1 200 OK
# ETag: "3"
# X-Frame-Version: 3
```

携带读取时版本保存（匹配 → 提交，版本 +1）：

```bash
curl -s -D - -X PUT http://localhost:8000/api/state \
  -H 'Content-Type: application/json' \
  -H 'If-Match: "3"' \
  --data @/tmp/frame.json
# HTTP/1.1 200 OK
# ETag: "4"
# X-Frame-Version: 4
# {"ok": true, "version": 4, "result": { ... }}
```

另一页面已先保存（版本已到 5），仍带着旧版本 4 的保存被拒绝并返回最新架体：

```bash
curl -s -i -X PUT http://localhost:8000/api/state \
  -H 'Content-Type: application/json' \
  -H 'If-Match: "4"' \
  --data @/tmp/frame.json
# HTTP/1.1 409 CONFLICT
# ETag: "5"
# X-Frame-Version: 5
# {"error": "架体版本冲突：您读取的架体已被其他页面/调用方保存，请合并后重试",
#  "conflict": true,
#  "version": 5,
#  "state": { "car": {...}, "layers": [...] },   ← 最新已保存架体（合并基准）
#  "result": { ... }}                            ← 最新架体的整架重算结果
```

取 409 中的 `state` 与本地编辑合并后，用响应里的新版本重试即可；确认要以本地
为准时可强制覆盖（等价于不带版本的老调用方式）：

```bash
curl -s -X PUT http://localhost:8000/api/state \
  -H 'Content-Type: application/json' \
  -H 'If-Match: *' \
  --data @/tmp/frame.json
```

版本号也可放在 `X-Frame-Version: 4` 请求头，或架体 body 顶层加
`"version": 4` 字段（该字段仅用于核对，不会写入架体结构）；版本头无法解析为
整数时返回 400。恢复示例同样推进版本：

```bash
curl -s -X POST http://localhost:8000/api/reset
# {"ok": true, "version": 6, "state": {...示例...}, "result": {...}}
```

## 载荷模型与约定

- 坐标系：俯视平面为 XY，原点在窑车台面左下角，X 向右、Y 向上，单位 mm；Z 为高度方向。
- 每层包含一块矩形棚板 `(x, y, w, d)` 与若干立柱；立柱**顶端托住本层棚板、
  底端落在下一层棚板上**，底层立柱底端落在窑车台面矩形内。
- 第 i 层棚板承受总载荷：
  `棚板自重 + 坯件重量 + 所有落在本板上的上层立柱点载荷`。
- 采用 **刚性棚板、有效立柱均摊** 的工程简化：总载荷由本层所有非悬空立柱
  平均分配；悬空立柱载荷为 0。若整层无有效立柱，该层载荷记为“丢失载荷”，
  不再向下传递，汇总区单独显示。
- 同层立柱底端距离 ≤ **10 mm**（`app/calc.py` 中 `TOL_MM`，可调）判定为落点
  重叠，合并为一个点载荷施加到下层棚板。
- 容量留空或填 0 表示“不限容量”，不参与超载判定。
- 顶层以上没有棚板：顶层立柱只承担把顶板载荷向下传递的作用。
- 失效推演：`POST /api/simulate`（或 `calc.calculate(state, failed=[...])`）把指定
  **非悬空**立柱标记为失效（输出 `failed=true`），视为不承载后整架按同一规则
  重新分摊；失效柱与悬空柱分开计数（`failedCount`），不触发悬空告警，只产生
  info 级提示，且不参与落点重叠判定与点载荷下传。
- 加柱建议：`POST /api/suggest`（或 `calc.suggest_posts(state, layer, spacing,
  capacity)`）在目标层承托面矩形内按 `spacing` 生成候选网格（自承托面左下角
  起，含边界），剔除与现有**非悬空**柱距离 ≤ `TOL_MM` 的点（严格大于才可行），
  对每个可行点深拷贝架体、追加一根新柱后调用同一套 `calculate` 整架重算，
  按 `(lostLoad, overloadCount, maxUtilization, x, y)` 升序取前 5；利用率只统计
  `capacity > 0` 的柱（容量 0 视为不限容量、不参与，全部不计时该方案利用率
  排最后）。候选点超过 4096 个（`MAX_SUGGEST_GRID`）直接返回加大间距的提示，
  不做穷举。整个过程不修改输入、不写盘；用户在前端确认后才通过
  `PUT /api/state` 持久化。
- 减载配额：`POST /api/load-shed`（或 `calc.load_shed(state)`）在几何不变、
  只下调坯件重量（r_i ∈ [0, w_i]）的前提下求解。第 i 层棚板总载荷为
  `T_i(r) = T0_i + Σ_{k∈run(i)}(w_k − r_k)`（T0_i 为全部坯件清零时的结构
  载荷，run(i) 为经「每层至少一根有效柱」连通到第 i 层的最高层及以下连续
  层段；某层无有效柱则载荷丢失、层段截断），有效柱均摊下最紧约束为
  `T_i ≤ c_i · min(capacity)`，即每个有限容量层给出一个后缀减量和下界。
  这是嵌套覆盖型线性规划，自顶层向下取 `d_i = max(0, T0_i + 后缀坯件 −
  c_i·capmin_i)`、逐层先减本层坯件、不足由近及远向上层回补即达最小总减量；
  建议重量向下取整到 0.01 kg（只减不增）留安全余量，再调用同一套 `calculate`
  重新整架校验。全部坯件清空后仍超载则无解（`feasible=false`），并返回清空
  工况下的剩余超载柱清单。整个过程不修改输入、不写盘；用户在前端确认后才
  通过 `PUT /api/state` 持久化。
- 层架抗倾覆：`POST /api/overturn`（或 `calc.overturn_check(state, ax, ay)`）
  与载荷分摊无关，只取几何与重量。第 i 层棚板与坯件合为质点
  `(x_i + w_i/2, y_i + d_i/2, H_i)`，其中 `H_i = Σ_{k=0..i} height_k`
  为该层累计高度，重量 `W_i = board.weight + wareWeight`；整架重心
  `G = ΣW_i·P_i / ΣW_i`。支撑多边形取底层（i=0）非悬空（底端在窑车台面
  矩形内）立柱落点经 Andrew 单调链算法求得的凸包（坐标完全重合的落点去重，
  面积须大于 `OVERTURN_EPS_MM = 1e-6 mm²`）。水平加速度 `(ax, ay)` g 下
  投影 `P = (Gx + ax·Gz, Gy + ay·Gz)`（惯性力 `m·a` 产生 `a/g·h` 的等效
  偏心，a 以 g 计故系数为 1）；带符号最短距离为 P 到凸包各边**线段**距离的
  最小值，P 在逆时针凸包的任一边右侧（叉积为负）即取负号：`d>0` 稳定、
  `|d|≤1e-6` 临界、`d<0` 倾覆。任一层无有效承托（落在承托面矩形内的立柱
  为 0 根）、落点不足 3 个不共线点、整架重量为 0 或空架时返回
  `evaluable=false` 与明确原因，不做判定。整个过程只读、不修改输入、不写盘。
- 逐层装货顺序：`POST /api/loading-sequence`（或
  `calc.loading_sequence(state, ax, ay)`）在架体几何不变、**保留全部棚板
  自重**的前提下，先令全部 `wareWeight=0`（此时须有 `Σboard.weight>0` 才能
  求重心），再把坯件重量大于零的层（候选层，至多
  `MAX_LOAD_SEQ_LAYERS = 12` 个）视为每步整层加入的对象。任一步装货状态与
  抗倾覆试算完全同构：该状态下各层重量为板自重加上「已装层」坯件，据此求
  整架重心、按 `(ax, ay)` g 平移投影并取底层落点凸包的带符号最短距离。
  候选层数为 m 时状态空间为 2^m（m≤12 → ≤4096）：动态规划
  `best[S] = max_{k∈S} min(best[S∖{k}], margin(S))`（`best[∅] = margin(∅)`
  即坯件全零初始裕量），按掩码数值递增枚举保证子集先算；最优值相同的顺序
  按**层索引元组字典序**（自下而上）决胜，浮点按位比较——各子集一次矩均按
  候选层序号升序累加，同一子集结果逐位确定，故决胜无歧义。规划给出最优顺序、
  初始与每步的累计坯件重量/总重/重心/投影/裕量/判定，`allStable` 仅当初始及
  各步裕量都 `> OVERTURN_EPS_MM` 才为 true（临界 0 与倾覆均视为无法全程稳定）。
  无有效承托、底层凸包退化、初始棚板总重为 0、空架、无候选层或候选层 >12 时
  返回 `planable=false` 与明确原因。整个过程只读、不修改输入、不写盘。
- 连续窑门通行：`POST /api/door-passage`（或 `calc.door_passage(state, doors)`）
  与载荷/重量无关，只取架体 X 向几何与层高。台面（z=0 上 `[0, car.w]`）与各层
  棚板（z=累计高度 `H_i=Σ_{k≤i} height_k`，横向 `[x, x+w]`，宽 0 的件不计）
  构成外廓件集合；最高点 `H=Σheight`。第 j 道门开口 `[c_j−w_j/2, c_j+w_j/2]`、
  净高 h_j：`h_j < H` 直接阻断（`blockReason="height"`）；否则外廓各件平移 s 后
  均须在开口内，本门区间 `I_j=[max_k(o_l−left_k), min_k(o_r−right_k)]`，
  `I_j` 自身为空是单门宽度不足（`"width"`）。可达性按门序递推：首门前位置为
  单点 `{0}`，进入第 j 道门时把上一可达区间扩张为 `[lo−m_j, hi+m_j]`（m_j 为本段
  最大横移量），与 `I_j` 求交，首次空交集即阻断（`"reach"`，附两区间、缺口与
  偏向）；因此各门单独有区间、序列却不可达时同样阻断。全程可达时回溯位置序列：
  末门取其可达区间中最接近 0 的值，自后向前 `s_k=clamp(s_{k+1}, 可达区间_k)`，
  每段移动必满足 `|s_k−s_{k−1}|≤m_k`（s₋₁=0）；逐门净空为
  `左=(envL+s)−o_l`、`右=o_r−(envR+s)`、`顶=h_j−H`（接触 0 即可通过，容差
  `DOOR_PASSAGE_EPS=1e-9`）。空门列表按全程可达（附 `note`）；没有任何层时
  `evaluable=false`；门参数非有限数值、宽/高非正、横移为负抛 ValueError（API 400）。
  整个过程只读、不修改输入、不写盘。
- 轮组承载：`POST /api/wheel-load`（或 `calc.wheel_load_trial(state, params)`）
  取**底层（i=0）非悬空立柱**（底端落在台面矩形内，含容量 0 的柱）的落点 (x,y) 与
  整架计算给出的**实载**为点载荷；同一点（完全相同坐标）的多根柱载荷在分配时
  **合并为一个点**。矩形四轮由 `(xLeft,yFront)/(xRight,yFront)/(xLeft,yRear)/
  (xRight,yRear)` 给出（必须 `xLeft<xRight`、`yFront<yRear` 且四点都在台面
  `[0,car.w]×[0,car.d]` 内，额定载荷均须 >0，否则 ValueError→400）。单点
  `P(x,y)` 的双线性份额为
  `R_FL=P·(xR−x)/(xR−xL)·(yR−y)/(yR−yF)`、
  `R_FR=P·(x−xL)/(xR−xL)·(yR−y)/(yR−yF)`、
  `R_RL=P·(xR−x)/(xR−xL)·(y−yF)/(yR−yF)`、
  `R_RR=P·(x−xL)/(xR−xL)·(y−yF)/(yR−yF)`；
  四个系数对平面任意位置恒和为 1，所以**落点越出轮组矩形只是让远端系数为负
  （杠杆外推），负反力原样保留、绝不截零**——截断会同时破坏竖向力平衡与
  绕 X/Y 轴力矩平衡。`checks` 用未截断精确值核对：反力之和 = ΣP；绕过前轮
  X 轴力矩 `Σ R_(后轮)·(yR−yF) = Σ P·(y−yF)`；绕过左轮 Y 轴力矩
  `Σ R_(右轮)·(xR−xL) = Σ P·(x−xL)`（相对容差 1e-7）。逐轮利用率
  `reaction/rating`，`reaction > rating` 判超载，`reaction < 0` 判负反力风险。
  没有底层、或底层非悬空柱正载荷合计为 0 时返回 `evaluable=false` 与原因。
  整个过程只读、不修改输入、不写盘。
